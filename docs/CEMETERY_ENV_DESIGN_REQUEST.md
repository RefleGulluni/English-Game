# 发给：Codex 美术组（新对话）— Broken Graveyard 正式场景设计（第一轮：方向探索）

日期：2026-10-25。需求方：Claude（程序），用户拍板。

## 0. 这是什么

`art/cemetery_pixel_v1/` 那批地面板与物件是**验证用的样板**（证明了“整张地面板 + 独立物件 + 底座贴花”这套生产方式可行），不是正式场景。
现在开始正式设计 Cemetery 的第一个区域 **Broken Graveyard**。

流程和设计主角时一样：**先出几个方向给用户选 → 选定后再按房间生产、拆分素材**。
这一轮**只出整体效果图（Visual Target）**，不拆物件、不做底座、不做碰撞说明。

## 2. 主题（一句话）

> **Something after death failed to end correctly.**
> Broken Graveyard：**曾经有秩序的墓园，现在秩序正在失效。**

视觉气质：冷、湿、安静、低饱和、古老、腐朽、克制，但依然有绘画美感（成熟暗黑像素）。
不要：满屏纯黑、满屏蓝光、血腥、堆满哥特装饰。

可以出现的元素（World Bible §40）：破墙、墓碑、铁栏、枯树、湿石板、泥土、雾、远处的墓群；以及开着或坍塌的墓穴。

## 3. 这一轮要画什么

画 **Broken Graveyard 的“骷髅房间”**：这个区域里最重要的一屏，第一场完整战斗发生在这里。

出 **3 个方向（A / B / C）**，每个方向一张 960×540 的整体效果图。三个方向要**真正不同**，主要差在“这个墓园的空间是怎么围起来的”，因为这决定了出口长什么样。例如（仅供参考，可以提更好的）：

- **围墙院落**：四周是残破的矮墙和铁栏，出口是墙上的缺口或歪倒的铁门。
- **开阔坡地**：没有明确边界，墓群向雾里延伸，出口是伸出画面的小路。
- **下沉墓区**：中间低、四周高，有残破台阶，出口是向上的台阶或坡道。

## 4. 每张图都必须满足

| 项目 | 要求 |
|---|---|
| 尺寸 | 960×540 原生像素，整数网格，真像素整理（网格 → 调色板 → 边缘），无半透明、无抗锯齿 |
| 视角 / 光 | 与主角一致的 3/4 俯视；光源左上 |
| 尺度 | 图中放一个主角 `hero_B1_front_straight.png`（原尺寸贴进去，不缩放），用来检查比例 |
| 地面 | 湿泥 + 稀疏枯草为主；石板只是残缺小路（缺失、下沉、被泥盖、方向偶尔不合理） |
| 战斗区 | 画面**中上部**留一块清晰的空地，约 400×220 像素，不放墓碑和树。下方约 40% 高度以后会被战斗界面盖住，所以重要的东西不要放在最下面 |
| 骷髅位置 | 战斗区边上要有一座**打开或坍塌的墓穴**，让人一看就想“它是不是从这里爬出来的”。骷髅不要站在正中间（这一轮可以不画骷髅） |
| 入口 / 出口 | 一个入口 + **2～3 个出口**，都在画面边缘，一眼看得出“可以从这里走出去”。出口之间要分得开（例如一个在上边、一个在右边） |
| 可拆分 | 墓碑、树、墙、铁栏、墓穴等有高度的东西，以后都要拆成独立物件。所以它们之间、它们和地面之间要分得清，不要糊成一片 |
| Fracture | 克制：只在一两处出现“关系错误”（例如一段石板路错开、通向虚无）。**不要 glitch、撕裂、像素错位** |
| 颜色 | **饱和青蓝色是语言层专用**，世界里一点都不能有（积水可以是冷蓝灰，但必须低饱和）。不画语言符号 |
| 阴影 / 描边 | 角色和物件不画地面投影（Godot 处理）；不加整圈描边 |

可选：画面顶部边缘可以露出一点远景（远处的墓群、教堂轮廓、雾），但不能让人以为那里能走过去。
