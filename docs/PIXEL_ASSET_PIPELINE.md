# 像素素材制作手册

建立：2026-10-25（Claude）。来源：墓园物件经过四轮尝试才做对，本手册记录**做对的方法**和**踩过的坑**，让以后在任何对话、任何组都能复现。
适用：所有进入游戏世界的像素素材：场景物件、角色、敌人、NPC、掉落物。地面板的做法尚未验证（见 §8）。
知识库对应：Decision Log D-025～D-028；`02_SYSTEMS/04_Content_Pipeline/English_Game_Pixel_Asset_Production_Method.md`。

---

## 1. 一句话

> **AI 负责画出丰富的细节，人负责把细节放到正确的像素网格上。**
> 单件生成大方块像素风 → 一格还原成一个像素 → 逐块整理 → 先做一件试样进游戏验收 → 再批量做。

## 2. 谁做什么

| 角色 | 负责 |
|---|---|
| 用户 | 最终判断：“像不像同一个游戏”。用户在游戏里的直觉很准，数字检查不能替代 |
| Claude | 写需求（附图片路径）、脚本检查、放进游戏验收、记录到知识库 |
| Codex 角色设计组 | 主角、角色、敌人、NPC 及动画；**场景物件**（D-026） |
| Codex 美术组 | 地面与整体构图（构图图只定位置和空间，不是最终素材） |

**每个组就是一个对话**。同一组的多件事排先后顺序，不并行开两个对话。

## 3. 两个锚点（写需求时必须附路径）

| 锚点 | 路径 | 用来判断什么 |
|---|---|---|
| **主角 B1** | `art/character_design/hero_B1_front_straight.png` | **精致程度的标准**。所有世界素材放在它旁边，都不能显得更简单或更写实 |
| **北极星** | `art/pixel_test/source/graveyard_P_reference.png` | **感觉的参照**：明暗、冷暖、饱和度、像素密度。**不是颜色仓库**，每个地区有自己的颜色（D-027） |

对照图：`docs/reference/northstar_with_hero_B1.png`（主角放进北极星图）、`docs/reference/detail_density_compare.png`（精致程度对比）。
画风规则的唯一标准：知识库 Art Direction Bible v3 `_SpecLocked_CLEAN`。

## 4. 验收标准

### 4.1 硬规格（脚本能查）

运行：`python3 scripts/tools/pixel_check.py <文件...>`（最后一行自动给出主角作对照）。

| 项目 | 要求 |
|---|---|
| 透明度 | 只有完全透明 / 完全不透明（0 / 255），无抗锯齿、无半透明 |
| 饱和青蓝 | 0 个像素（语言层专用色；主角书上的印记除外） |
| 尺寸 | 以主角 96 px 为参照，按需求文档给的高度范围 |
| 原点 | 底边中心；立体部分和底座贴花两张图原点相同，画布底部透明留白不能裁 |
| 颜色数 | 与主角同一量级（主角 44 色；一件物件 20～50 色正常） |
| 相邻像素换色比例 | 与主角接近（主角 88%；合格的墓碑试样 86%）。**低于约 60% 基本就是平涂** |

换色比例只用来发现“太平”，**不能靠加杂点把它刷高**。

### 4.2 眼睛看（脚本查不了）

- **每一小块颜色都说得出是什么**：苔藓、裂纹、雨痕、地衣、受光边、压倒的草……没有说不出含义的随机杂点。
- **缩回 1 倍依然一眼认得出**是什么，轮廓清楚。
- **深色收边**：用该材质自己最暗的那档，不是统一黑线，不是整圈描边。
- 光从左上来；不画地面投影（接触阴影在 Godot 里做）；不要 glitch。
- 底座贴花要“长在泥里”：下沉的泥、翻土、压倒的枯草、碎石，范围略大于接触面。不能只有几小撮。
- 和主角并排 6 倍看，精致程度相当；放进游戏走一走，不像“贴上去的”。

## 5. 制作流程（已验证：墓碑试样，2026-10-25）

1. **单件生成**：一张图只画一个物件。要求“大方块的像素画，不要写实”，把主角的 8 倍放大图作为像素大小参考，纯色背景（如品红）方便抠图。生成工具给出的尺寸不一定听话（要 768 给了 1254），没关系，下一步按实际方块还原。
2. **找到真实的像素格**：分析生成图里方块的边界（墓碑试样约 12 个点一格，实际 10～14 不等），逐行逐列找格边。**不能**整体 resize，**不能**非整数比例缩放，**不能**平滑或取平均。
3. **一格还原成一个像素**：每格取中心那一个点的颜色。得到原生尺寸的图（墓碑试样 77×92）。
4. **逐块整理**：合并近似色（不加抖色）→ 清除背景色污染 → 删除 1～2 像素的孤立碎点 → 边缘颜色并入相邻材质 → 确认收边。不用程序“生成”新纹理。
5. **拆成两层**：立体部分（参与遮挡）+ 底座贴花（永远在角色脚下），同一原点，放到需求规定的画布里（整数位移）。
6. **QC 交付**：保留生成原图 → 还原后的原生图 → 和主角并排的 6 倍图 → `pixel_check.py` 的数字 → QA（写清每种小色块代表什么，**没做到的如实写出**）。
7. **先一件试样**：新类型的素材，先做一件，进游戏验收通过，再做其余的。
8. **要拼接的零件（墙、柱、栏杆、地砖……）**：不能各自生成。同一家族的新零件，**以已有零件的像素为底子改出来**（例如断墙 = 拿完整墙“打碎”右半边），石头种类、颜色、层高才对得上；柱子要“砌进墙里”，不带外凸的独立底座。交付时附一张**按游戏用法拼好的拼装图**，接口处放大检查。拼接列像素一致只能保证接口没缝，管不了两边的整体风格（D-029）。

## 6. 验收流程（Claude）

1. 读 QA，特别是“没做到 / 拿不准”。
2. `pixel_check.py` 核对硬规格和精致程度。
3. 看 6 倍对比图和生成原图（确认是还原而不是缩小）。
4. **放进游戏**：试走房间 `scenes/prototypes/props_v3/props_v3_room.tscn`，在脚本的 `LAYOUT` 里加一行 `["物件名", Vector2(x, y), null]` 即可（碰撞自动按物件的脚生成；物件名可带子目录，例如试样）。新旧版本并排摆在主角两边，方便对比。截图：`-- --capture=<目录>`。
5. 给用户开窗口，让用户自己走。**用户说通过才算通过。**
6. 通过后：把决定写进知识库 Decision Log，标准有变化的写进 Art Bible。

## 7. 写需求的要点（教训）

- **附图片路径**，不要只写“见某某章节”。画风用文字描述，三个人能想出三种颜色。
- **同时写上限和下限**：例如“要和主角一样精致（下限），但不能是随机杂点（上限）”。只纠正一头，就会从一个极端跑到另一个极端。
- **不要把参考图当颜色仓库**。
- **规格和现实冲突时，让对方停下来问**，或者先做一小块试样证明，不要自己绕过去。
- 文末写清“做完这个，下一个是什么”，组里接得上。
- 给 Codex 组的消息写成可直接转发的中文，开头标明“发给：xxx”。

## 8. 踩过的坑（2026-10-25 墓园）

| 轮次 | 做法 | 结果 | 原因 |
|---|---|---|---|
| 1 | 美术组 AI 生成整张写实大图（1672×941），按 1.74 倍缩到 960×540 | ✗ 像“缩小的照片” | 非整数缩小，像素块对不上网格；底子是写实画 |
| 2 | 美术组截一块，程序分区换色 + 减色 | ✗ 整体变蓝，V2 有长方形补丁 | 滤镜修不了底子；为了让主角醒目，整体冷色过头 |
| 3 | 角色组用程序在原生画布上摆色块，8 色 | ✗ 真像素但太平，“色彩单调” | 需求写了“每种材质 3～4 档、颜色成块”，矫枉过正 |
| 4 | 角色组单件生成大方块像素风 → 逐格还原 → 整理 | ✓ 44 色 / 86%，和主角像同一个游戏 | AI 出细节 + 人管网格 |
| 5 | 同法做完 9 件，墙、柱、断墙**各自生成** | ✓ 单件都好；✗ 拼成一排时违和（柱子像站在墙前、墙和断墙接不上） | 零件分开生成，乱石 / 条石、颜色、层高不同；柱子自带外凸底座。处理：保留，分成两个墙家族，补齐配套零件（D-029） |

**地面板还没有用第 4 种方法做过**，可能需要另找办法（地面面积大、要和物件衔接）。做之前先出小块试样。

## 9. 多样性（同一场景里不能满是同一个物件）

| 方法 | 谁做 | 说明 |
|---|---|---|
| 形状家族 | 角色组 | 同类物件多种形状（墓碑：圆顶、平顶、尖顶、方尖碑、小矮碑、平躺墓板、十字碑） |
| 状态 | 角色组 | 直立 / 歪斜 / 断裂。**像素画不能靠旋转来“歪”**，必须单独画 |
| 下沉深浅 | Claude（Godot） | 图往下挪，下半截藏在底座后面，像素不受影响 |
| 换石头颜色 | Claude（Godot） | 调色板替换：每种颜色一对一换成另一种，形状不动 |
| 摆放规则 | Claude | 相同物件不挨着；穿插小物件（碎石、花瓶、蜡烛、小石堆）；有的整齐成排、有的东倒西歪 |
| 墙的家族 | 角色组画，Claude 摆 | 同一排墙只用同一家族；不同家族区分区域：墓园用 A 乱石墙（古老、后来补砌）、B 条石墙（曾经讲究的部分）+ 铁栏 + 门柱 |
| **不能用** | — | **左右镜像**：光源会变成从右上来，一眼就错 |

## 10. 新对话的开场模板

给某个组开新对话（或者旧对话太长需要换）时，第一条消息可以这样写：

> 发给：Codex ××组
>
> 你负责 English Game 的 ×× 素材。开工前请按顺序阅读：
> 1. 仓库 `docs/PIXEL_ASSET_PIPELINE.md`（像素素材制作手册，必读，特别是 §4 标准、§5 流程、§8 踩过的坑）；
> 2. 仓库 `art/README.md`（素材目录，哪些在用、哪些作废）；
> 3. 本次需求：`docs/××_REQUEST.md`。
>
> 仓库位置：`~/Documents/GitHub.nosync/English-Game`（旧路径 `~/Documents/GitHub` 是空壳，不要写进去）。新类型的素材先做一件试样，交付后停下等验收。
