# Pixel Art Direction v3 — 决定记录与 Godot 实现

> **日期：** 2026-10-20 ～ 2026-10-22
> **美术规范原文：** Obsidian `English_Game_Art_Direction_Bible_v3_Pixel_World_SpecLocked_CLEAN.md`（以它为准）
> **本文档：** 记录这几天定下了什么、为什么这样定，以及验证原型在 Godot 中是怎么实现的，方便以后接手正式开发时直接参考。

---

## 1. 一句话结论

> **The world is pixel and broken. Language is precise and luminous.**
> 世界是像素化并破碎的；语言是精确且发光的。

成熟、克制的暗黑像素风。每个房间用一整张地面板打底，墓碑、树等高物件全部独立并配“底座贴花”，角色是 96 px 真像素帧动画，语言符文和世界同像素、靠发光与几何区分。

---

## 2. 我们是怎么走到这里的

| 阶段 | 尝试 | 结果 / 学到什么 |
|---|---|---|
| 1 | 半写实绘画风 + 石板/泥地无缝纹理 + 双网格交界 | 石板铺满太工整，不像墓地；交界生硬 |
| 2 | 石板 A/B/C 三种细节程度 | 细节越多 AI 感越重；地面和物件像两个人画的 |
| 3 | 泥土枯草地面 + 独立石板小路 | 墓地气质对了，但写实地面与风格化石板不统一 |
| 4 | 像素风 vs 限制手绘 同场景对比 | **用户一眼选中像素风**（P 版本图成为北极星） |
| 5 | 64 / 96 / 128 px 主角实机切换 | 选定 **96 px + 960×540** |
| 6 | 符文：平滑 / 细像素 / 与世界同像素 | 选定 **与世界同像素** |
| 7 | 地面：双网格瓦片 vs 整张地面板 | 选定 **整张地面板** |
| 8 | 物件“漂浮”、遮挡、碰撞 | 底座贴花 + 整体半透明 + 按实际落地范围碰撞 |

**关键经验：** 所有最终决定都是**在 Godot 里亲眼看过之后**做的。纸面分析曾推荐过双网格瓦片和平滑符文，实机一看都被推翻。

## 3. 已确定的规格

### 3.1 画面与尺寸

| 项目 | 规格 |
|---|---|
| 主角原生高度 | **96 px**（约占屏幕高度 18%） |
| 原生画面 | **960×540**；1080p 放大 2×，4K 放大 4×，必须整数倍 |
| 地面逻辑格 | 32 px（主角 = 3 格高） |
| 真像素 | 原生分辨率交付，无抗锯齿，Alpha 只有 0 / 255 |
| 调色板 | `art/cemetery_pixel_v1/cemetery_palette.gpl`（墓园子调色板，64 色） |
| 视角 / 光源 | 3/4 俯视；光从左上来 |

### 3.2 语言层

- 符文、短关键词与世界**同像素密度**。
- 区别靠：自发光、全画面唯一的饱和青蓝、精确几何、不受雾/阴影/环境色影响、平稳匀速动画。
- 发光扩散、雾、光照可以平滑；**符文几何本身是像素**。
- 例外：释义、例句、对话等长段英文用清晰易读的字体。

### 3.3 场景分层（从下到上）

1. **地面板**（Ground Decoration Plate）：每个房间一张，只含平面内容
2. **底座贴花 + 装饰贴花**：树根、翻土、枯草丛等，永远在角色脚下
3. **不可见逻辑层**：碰撞、导航
4. **独立高物件**：只保留立起来的部分，参与前后排序
5. **角色 / 敌人**
6. **前景遮挡**
7. **光、雾、特效**
8. **语言层**

### 3.4 物件规则

- 高物件 = **立体部分**（参与排序和遮挡）+ **底座贴花**（贴地，永远在脚下）。两张图原点相同（底边中心）。
- 物件**不画地面投影**。
- 角色站在物件后方时，**整个物件（立体部分 + 底座）一起**渐变半透明。
- 碰撞按物件真实的落地范围设置（例如枯树是覆盖树根的椭圆）。

### 3.5 用户明确不要的

- 角色描边（试过，用户不喜欢）
- 完全平滑的高清符文
- 整片铺满的石板地面
- 半写实 / 绘画式的世界渲染
- Fracture 做成像素故障特效（glitch）

## 4. 素材交付规范（给美术组）

- 所有素材放在 `art/` 下，每批附 `qc/*_QA.md` 检查记录。
- 透明 PNG；物件的“脚底 / 底座中心”放在图片**底边中心**；不要裁掉透明留白（留白是原点约定的一部分）。
- 每个高物件交付 `xxx.png`（立体部分）+ `xxx_base.png`（底座贴花），并在 `props/NOTES.md` 写明占地格数与碰撞建议。
- 立体部分与底座**重叠的像素颜色必须完全相同**（程序会把重复像素只保留在底座里）。
- 树枝等横向伸展的部分，最好长在角色头顶以上（离地约 100 px 以上），避免和角色处在同一深度时前后难以分辨。

## 5. Godot 实现（验证原型）

### 5.1 原型文件

| 文件 | 作用 |

| [scripts/prototypes/graveyard_room/graveyard_room.gd](../scripts/prototypes/graveyard_room/graveyard_room.gd) | 渲染、分层、物件、底座、遮挡、碰撞、动画、截图 |
| [scenes/prototypes/pixel_room/pixel_room.tscn](../scenes/prototypes/pixel_room/pixel_room.tscn) | 尺寸与符文风格对比（64/96/128、三种分辨率、三种符文） |
| [scripts/prototypes/pixel_room/language_sigil.gd](../scripts/prototypes/pixel_room/language_sigil.gd) | 语言符文的绘制（两个原型共用） |
| `scenes/prototypes/terrain_v2/`、`scripts/prototypes/terrain_v2/` | 已废弃的半写实双网格地形研发记录 |

**运行方式：** Godot 编辑器打开场景后按 **⌘R**（运行当前场景），或命令行：

```
/Applications/Godot.app/Contents/MacOS/Godot --path . res://scenes/prototypes/graveyard_room/graveyard_room.tscn
```

**墓园验证房间按键：** WASD 移动 · T 切换地面（瓦片 / 地面板 / 目标图）· G 阴影与光 · L 语言层 · O 角色描边（默认关）· F 全屏 · H 隐藏说明。
加 `-- --capture=<绝对路径>` 会自动截图并退出，用于回归对比。

### 5.2 真像素渲染

- 世界渲染进一个 **960×540 的 SubViewport**：
  - `canvas_item_default_texture_filter = NEAREST`
  - `snap_2d_transforms_to_pixel = true`、`snap_2d_vertices_to_pixel = true`
- SubViewport 的画面用 TextureRect 显示，**放大倍数 = floor(窗口像素 / 原生尺寸)**，保证整数倍，居中显示。
- 运行时把窗口的 `content_scale_mode` 设为 DISABLED，这样倍数按**真实屏幕像素**计算（Retina 屏上 1280×720 的窗口其实是 2560×1440 像素）。
  这是原型里的做法，**没有改 `project.godot`**。

### 5.3 语言层

- 符文画在**另一个同为 960×540 的透明 SubViewport** 里，关闭抗锯齿，所以一个符文像素 = 一个世界像素。
- 它不在世界的画布里，所以世界的 CanvasModulate（冷色调）不会影响它，满足“环境独立性”。
- 绘制逻辑在 `language_sigil.gd`：正圆、等边三角、节点菱形、柔和光晕，匀速旋转与呼吸。

### 5.4 场景结构（墓园验证房间）

```
SubViewport (960×540)
└── World
    ├── Ground        地面板 / 瓦片 / 目标图（T 切换）
    ├── TileExtras    瓦片模式专用：装饰贴花 + 石板小路
    ├── Bases         底座贴花 + 枯草贴花（永远在角色下方）
    ├── Sorted        y_sort_enabled：所有高物件 + 主角
    ├── Walls         房间边界碰撞
    └── CanvasModulate 冷湿环境色
SubViewport (语言层, 960×540, 透明)
└── LanguageSigil
```

### 5.5 物件的处理流程（`_make_prop`）

1. **找真正落地的位置**：美术组把树根移进底座后，树的立体部分在 PNG 底边上方 46 px 处就结束了。程序找出立体部分最低的不透明像素行，把节点**抬到那里**（`gap`），精灵偏移同步下移，画面位置不变。
   这样前后排序、碰撞都以“树干落地处”为准，角色站在树根上时不会被整棵树挡住。
2. **去掉重叠像素**（`_without_overlap`）：立体部分和底座里**颜色完全相同**的重叠像素，只保留在底座里。否则两层同时半透明时，重叠段会叠出一条深色带。颜色不同的像素（例如墓碑石座压在泥土上）保留在立体部分。
3. **接触阴影**：有底座的物件不加程序阴影（底座的湿泥已经承担了接触感）；没有底座的物件，按自身底部轮廓压扁生成一个像素阴影。
4. **碰撞**：碰撞数据以 PNG 原点为准（来自美术的 NOTES），挂在偏移 `gap` 的 StaticBody 上；支持矩形和椭圆（20 点多边形）。

### 5.6 遮挡半透明

- 每帧检查：角色在物件后方（角色 y < 物件排序点），并且角色身体落在物件图像范围内。
- 满足时，立体部分**和它的底座**一起用 `move_toward` 渐变到 0.45 透明度，离开后再渐变回来。
- 曾试过“只在角色周围开一个透明窗口”的 shader，用户更喜欢整体半透明。
- 没有用像素网点透明，因为网点在 v3 中是 Ghost 的 FADED 状态专用语言。

### 5.7 角色

- 6 帧侧向行走（80×96，原点在脚底中心），每帧 120 ms，朝左用镜像。
- 碰撞是脚下一个 22×8 的小矩形，让角色能贴近物件。
- 身上挂一个暖色 PointLight2D，配合冷色环境，让角色从地面中“亮”出来。

### 5.8 双网格瓦片（可选方案，已实现但不再默认）

- 显示格比逻辑格错开半格；每个显示格看四个角的地形。
- 图集索引：`index = 8×TL + 4×TR + 2×BL + BR`，图集坐标 `(index % 4, index / 4)`。
- 泥↔草、泥↔积水两套过渡；草和积水之间强制隔一圈泥（没有草↔水的过渡图）。
- 纯色格随机使用 4 个无缝基础变体。

### 5.9 原型里的“临时做法”（迁移到正式游戏时要改）

| 原型做法 | 正式游戏应改为 |
|---|---|
| `Image.load_from_file` 直接读 PNG，不依赖导入 | 用编辑器导入的纹理，导入设置为 nearest、无 mipmap |
| 运行时关闭 `content_scale_mode` | 在 `project.godot` 中设定 960×540 原生分辨率 + 整数缩放（**改之前需用户同意**） |
| 物件、底座、碰撞都在脚本里创建 | 做成可复用的物件场景模板（立体部分 + 底座 + 碰撞 + 淡出），关卡里直接摆放 |
| 物件位置写在脚本常量里 | 在编辑器里手动摆放，每类房间多套布局 |

## 6. 已知问题与待定事项

- **横向伸展的树枝**：和角色处在同一深度时，前后关系难以分辨。候选办法：美术规则（树枝高于头顶）或把树冠拆成独立一层。
- **行走动画**：6 帧测试中剑和衣摆仍有轻微闪动；只做了侧向，上下方向未做。AI 生成序列帧的一致性仍需验证，预计需要人工修整。
- **每类房间需要几张地面板**、地面板的生产流程，尚未定。
- **语言层的发光**目前只是光晕，还没有真正照亮周围环境（v3 要求“可轻微照亮周围”）。
- **另外两个验证场景**：Abandoned Station（车站）与 Eleanor’s Shop（室内）尚未验证。
- 正式调色板（全局 + 各区域）、描边强度（目前无描边）、Camera 跟随方式尚未锁定。

## 7. 已废弃的方案（不要重复走）

| 方案 | 废弃原因 |
|---|---|
| 半写实 / 绘画式世界 | AI 感重，素材之间风格漂移，帧动画成本高 |
| 整片石板铺地 + 无缝纹理 + 交界笔刷 | 太工整，不符合“秩序正在失效”的墓园 |
| 双网格瓦片作为默认地面 | 实机中平、空、机械，明显不如整张地面板 |
| 高清平滑的语言层 | 和像素世界割裂，像“贴上去的另一套渲染” |
| 只在角色周围开透明窗口 | 用户更喜欢整个物件一起半透明 |
| 角色描边 | 用户不喜欢 |

相关研发素材保留在 `art/cemetery_kit_v2/`（半写实阶段）与 `art/pixel_test/`（尺寸测试），仅作记录。
