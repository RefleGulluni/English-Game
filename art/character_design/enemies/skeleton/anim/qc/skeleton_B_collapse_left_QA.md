# 骷髅 B 左侧散架（§21.2，单头骨版）

本次只交左侧。12 帧，1152×96 横条；每格 96×96、脚底锚点 (48,96)。总长 **1280 ms**，不循环，停在第12帧。

## 前半段保留什么

前5帧沿用用户认可的第二稿顺序：站姿 → 垂头、腕松 → 膝部失力 → 关节分开 → 上身与骨盆断开下落。没有重新生成前5个动作。第1帧直接使用左侧标准图。第2～5帧来自原第二稿对应格，只有逐格还原、原48色归色、原生比例与落点整理。

第二稿是放大的生成图，并非已经交付的96×96帧，所以这里的“保留”指动作及构图，不声称PNG与那张大图逐像素相同。原生还原后，第2～5格高度分别105/96/97/99；为了在96画布中保留持续下坠，分别整理到94/88/80/76高。只选择骨干/布面内部的原生扫描行重新登记，保留每个输出像素的源行号；没有整体平滑缩放、非整数resize、镜像或旋转。行表见 frame_records.json。整理后的前5帧单独留档 preserved_first5_*.png，后半段制作未改变它们。

## 一个头骨，持续落到同一个位置

先把公共骨堆分成“无头骨身体”与“唯一头骨”两层，归档 canonical_headless_heap.png / canonical_single_skull.png。后半段没有把带头的整张骨堆贴在掉落头骨后面。每帧只绘制一份头骨；头骨朝右下移动，落地以后换用已画好的滚转视面，再进入最终姿态。没有软件旋转头部图片。

第6～7帧还在落的胸、肩、手臂来自第5帧原生零件；同时不显示骨堆里的胸/肩/手组，避免同一骨组提前重叠出现。第8帧开始换为落地后的对应组；布比长骨晚落，最后落定。第6～7帧清理了分组后1～5px的孤立暗色碎边，这些不是另画的小骨头。

## 哪块骨头去了哪里

图号对应 skeleton_B_collapse_left_map.png：1 头骨→右侧；2 右肩与双钉→左侧；3 胸廓/脊柱→中后部拱起骨群；4 骨盆→中部布下；5 斜披裹尸布→中部覆盖；6 长骨/足骨→下缘；7 手臂/手骨→前缘。

头骨是这次严格追踪的一份显性对象。其他部位按骨组保持先后与遮挡关系；终态布下面的骨盆、细小肋骨不具备可独立辨认的逐根编号，因此不声称能证明每一根被挡住的小骨在中途的全部位置。请在游戏内继续看第7→8帧的落地换面是否自然。

## 制作来源与实际限制

初始第二稿由内置image_gen生成；原图中第6、7格含两个头，明确是弃用的失败姿势。本轮仅取其前5格以及第6格左侧独立头骨的已画滚转视面，没有使用其带双头的完整落地格。参考还原图 palette_native_06/07 仍保留在 sources 供复核，它们不是交付动画帧。

生成色块周期约3～4个显示像素，存在非严格等距边界；本轮按约4px的大块边界逐格恢复，完整边界在restoration_grid.json。这是对实际画格的估计，不是把生成图声称为数学上完全规则的像素网格。

前5帧原生比例清理、后半段骨组换面及头骨滚动仍需要游戏里判断。头骨只有一份、端点相同、颜色透明等技术检查不能代替动作观感验收。此次未修改Godot工程。交付后停下，等用户验收。
