# Cemetery · 风格统一样品 QA

2026-10-25。依据：已完整阅读 `docs/CEMETERY_STYLE_TEST_REQUEST.md`。仅处理 A 图的 `[600,960) × [180,440)`，原生 360×260；没有重做整屏，没有改动上一轮 design 或样板。

## 结论

**更推荐 V2。** 它的墓碑正面、墓穴盖板和地面已变成明确的大色块，主角的棕色外套更容易从偏冷灰的地面里分离。V1 保留更多砖石与破损信息，但泥地、碑面仍有细碎簇，放到主角旁边时，比 V2 更容易保留上一轮的“缩小写实图”感觉。

本轮是可放入游戏比较的风格样品，**不宣称两版已经完全达到逐像素人工精修标准**。主要未通过项是生成源网格不完全一致，以及部分小材质没有实际用满 3～4 档。下文列出具体边界。

## 每版做了什么

| 项目 | V1 · 收敛版 | V2 · 风格化版 |
|---|---|---|
| 构图 | 保留墓穴、右侧盖板、墙栏、竖碑和十字碑的空间关系 | 同一构图，减少物件表面信息 |
| 石材 | 保留砖缝、盖板斑块和部分碎口，明确受光顶面与暗侧面 | 盖板合并为大平面；墓碑减少斑点；墙砖使用更完整的块面 |
| 边缘 | 用石材深灰和铁材暗灰收住转角、右侧和下沿 | 暗边更连续，顶部受光边仍留亮色；没有统一加黑色外轮廓 |
| 地面 | 减少颗粒，保留较多中小泥块与草束 | 大块冷灰泥地与灰蓝积水，草束集中在物件附近 |
| 原生可见颜色数（不含主角） | **19** | **16** |
| RGB / 透明度 | RGB，完全不透明 | RGB，完全不透明 |
| 世界层饱和青蓝 | 0 色 | 0 色 |

原图截块实测 62 色。八邻域内没有任何同色相邻像素的“孤立像素”计数：原图 **38,760**；V1 **2,090**；V2 **594**。这个数只用于观察碎粒减少，不等于像素艺术质量评分，也不能代替检查轮廓、材质与构图。

## 材质明暗档位

先定义每种材质自己的色阶，再按材质归属映射；不是把整张图随意压成同一个全局近似调色板。石材暗边、铁栏暗边和坑内暗面各有色阶。小面积材质可以共用接近的暗色，V2 有一档铁材/坑内暗色共用，因此各行数量相加不一定等于整图颜色数。

| 材质 | V1 定义 / 实际出现 | V2 定义 / 实际出现 |
|---|---|---|
| 石材 | 4 档 + 1 档高光 / 5 色 | 4 档 / 4 色 |
| 铁栏 | 4 档 / 2 色 | 4 档 / 2 色 |
| 湿泥 | 4 档 / 4 色 | 4 档 / 4 色 |
| 积水 | 4 档 / 1 色 | 4 档 / 2 色 |
| 枯草 | 4 档 / 4 色 | 4 档 / 3 色 |
| 墓穴内壁与深土 | 4 档 / 3 色 | 4 档 / 2 色 |

**没有完全满足“每种材质实际都用 3～4 档”。** 铁栏与积水实际只使用 1～2 档，V2 坑内也只有 2 档。没有为了填满色数而给所有细线增加亮边；但如果将该项作为严格最低档数验收，后续仍需逐材质补齐有意义的侧面与受光面。完整色值见 `style_material_ramps.png` 和 `style_palette_V1.gpl` / `style_palette_V2.gpl`。

颜色检查口径：HSV 色相 160°～260° 且饱和度 S≥0.35，V1/V2 世界层均为 0。灰蓝积水保持低饱和。**此检查不作用于主角 Lexicon：它的青蓝印记按要求保留。**

## 网格与制作方法：如实说明

1. 原始截块直接从 A 图裁出，没有缩放。参考图只做了 nearest 的 3×、4× 或 8× 整数放大。
2. 使用内置 image_gen 进行两种强度的风格重画。第一批返回 1476×1066，未遵守指定的 4× 格，两版区别也不够，因此未采用。
3. 接受稿使用 **1536×1024 标准画布**，左上 **1080×780** 为绘图区，其余为工作留白。按固定步长 3 从绘图区采样：`source[0:780:3, 0:1080:3]`，直接得到 360×260。没有使用 1476→360、1672→960 之类的非整数缩放，也没有用模糊、抗锯齿或扩散抖色。
4. 在原生样品网格上确定材质范围、规整各材质色阶和选择暗边颜色；对比图最后才贴入原色主角。

**源网格仍有重要限制：** 图像模型并没有让绘图区里的每一个 3×3 单元都严格同色。按“单元内任一通道极差大于 12”的检测，V1 有 36,816 个单元，V2 有 15,594 个单元存在变化，绘图区共 93,600 个单元。因此不能说“已找回生成图唯一且完全统一的真实像素格”。本轮做到的是固定整数采样后的原生 1px 离散网格和受控色阶；还没有完成每个物件的逐簇手工重画。

这一点比上一轮避免了非整数比例缩放，但仍不应将“整数采样”本身当作风格已经统一的证明。最终判断看 8× 边缘和游戏里的角色贴近观察；V2 的简化明显更接近目标，V1 仍有碎簇。

## 没做到或仍拿不准

1. **V1 仍然偏碎。** 碑面与泥地的杂色远少于原图，但仍没有主角那种逐簇设计感；它是保守对照，不是我建议直接推广到整屏的版本。
2. **V2 有变平的代价。** 墓穴盖板较空，坑内层次较少，湿泥和积水的材质区别也被压缩。后续可补少量有方向的裂口、内壁结构或积水岸沿，但不能再恢复满地细粒。
3. **整体冷灰调整比“略偏冷”更强。** 有利于主角分离，但石材与泥地的色温差也变小。推广到整屏时应保留少量偏暖的石材受光面与枯草，不能让整个墓园变成同一片蓝灰。
4. **轮廓不是原截块的逐像素复刻。** 重画后墓穴、石盖和部分碑沿有少量形状与位置变化；大体空间关系相同，不能作为原图的无缝替换补丁直接贴回整屏。
5. **暗边还没有逐段人工验收。** V2 右侧竖碑的顶部亮边、右侧暗边和两片碑面更清楚，但墓穴碎口和局部墙脚仍有零散像素。材质归属整理也存在边界误判的可能，不能声称每一段暗边都已精修到主角标准。
6. **投影检查仅为目视。** 没有添加角色或物件地面投影，也没有 glitch。个别物件脚边的深色土块仍可能被看成接触阴影；后续拆物件时应把这些与真正的物件暗侧面再区分。
7. **尚未做实机判断。** 本轮未改 Godot 场景；角色移动到墓碑旁、动态光照下的效果，留给这次游戏内样品对比确认。

## 把整张 960×540 做到这个标准：建议方法与工作量

建议采用 **V2 的大色块与边缘纪律**，再给墓穴内部保留少量 V1 的结构。不要将整张 A 再缩一遍或套同一套滤镜。

1. 先固定主角原图、两块石材、一个铁栏段、湿泥和积水作为原生规范页，确定各材质 3～4 档、选择性暗边和最大纹理密度；全程以 1×、2×、8× 查看。
2. 在 960×540 原生画布上先组织大块泥地、积水和草地；战斗区保留安静冷灰底色，草束与细节主要向物件脚边集中。先检查主角站在数个位置是否都清楚，再加细节。
3. 墓穴、墓碑、墙柱、墙砖、铁栏等按物件原生尺寸逐个整理轮廓与面，不让图像模型自行决定不同局部的像素密度；重复结构可以复用已通过的砖石与栏杆处理。是否拆出独立资产属于后续正式生产，这轮不做。
4. 做三遍分别有目标的检查：形体与暗边 → 材质色阶与色块 → 1px 孤点、细线和相邻块关系。不能用最后一次减色来替代前两遍。
5. 将原色主角放在墓穴旁、石墙前、泥地和积水附近检查，再进 Godot 用 nearest 和整数缩放走动验收。

**规划估算：第一张整屏约 3～5 个有像素绘制经验的美术人日**：规范与代表物件约 0.5～1 天，原生地面与高物件整理约 1.5～2.5 天，整屏合成、边缘复查和实机往返约 1 天。构图大改、人工逐像素完全重画，或额外拆分底座/碰撞，都可能增加时间。这个范围是生产安排的估算，不是由两张 AI 样品证明的工时承诺；后续同类房间可复用通过的物件和规则，通常会更快，但地面仍需单独组织。

## 文件与保护

已保存接受稿与未采用初稿的手写提示词、实际采样参数、材质色阶及检查数据。`assemble_style_test.py` 只负责整数采样、材质色阶整理与对比组装，场景重画来自内置 image_gen；没有用程序凭空绘制新墓园。

`backups/before_material_labeling/` 是本轮工作副本在材质映射与冷灰修正前的恢复备份，不是当前样品。工作参考放大图与临时校验清单在验证后移入系统废纸篓；原始生成输出保留在生成器默认目录作为来源。仓库原有文件、上一轮 design、样板和原主角均未改动。
